# 纯客户端发现与推荐

2026-10-26。保留现有 SwiftUI/AVPlayer App、订阅、下载、PIN 与过滤模块；没有新建后端、付费 API、账号或编辑精选系统。

原始探测摘要：public-source-probe.json、episode-lookup-probe.json、episode-batch-lookup-probe.json。只保留必要事实和标识，不把整段节目文案当交付资料。分类关系取自 [Apple 官方分类规范](https://podcasters.apple.com/support/1691-apple-podcasts-categories)；110 个标准 ID 与中繁体别名来自任务 B 已采集的 Apple 公开目录观察及补充的公开分类 Feed，证据见 category-mapping-evidence.json、category-id-probe.json。目录内容会随地区和时间变化，单次成功不等于服务 SLA。香港区尚未单独现场验证，使用相同公开接口与失败回退。

客户端 `quietcast-tools smoke-home CN` 已实际跑通节目榜/单集榜 → Lookup → RSS → 过滤 → 缓存。探测仅取少量候选，App 默认最多40个榜单候选，RSS并发4；不足时从目录补充候选池。使用新 GUID 对齐后的最终结果见 VERIFICATION.md。

## 首页栏目及命名

- 继续收听：设备本地逐集位置。
- 订阅更新：已有订阅的 RSS 未播放单集。
- 热门播客：公开 Apple 节目榜，过滤后仍显示来源名次，允许出现缺号，不重新伪造排名。
- 热门单集：公开单集榜，必须由 Lookup ID/GUID（无 GUID 时精确 enclosure）对齐当前 RSS；缺失或无法确认的条目跳过，不任意选同名集。
- 你可能喜欢：本地偏好评分，**不是苹果推荐**。
- 分类探索：历史、科技、科学、社会文化、教育、新闻、心理健康等传统播客方向；子分类可继续进入。没有复制苹果的有声书/网文/小说营销栏目。
- 发现新节目：按日轮换分类检索，指“对本机尚未订阅/收听的节目”，不声称是刚上线的新发行节目。
- 更多播客发现：官方榜单过滤后不足时，另列目录补充内容；补充条目不会被赋予官方名次。

如果公开榜单整体获取或解析失败：有旧有效榜单时优先保留并标记更新失败；首次无缓存时改用目录发现，并把标题改为“播客发现”或“新近单集”，来源明确标注“非官方榜单”。不采集未公开的编辑精选或内部接口。

## 本地推荐算法

每个订阅分类加3；收藏单集对应分类加4；历史按最近时间指数衰减，并按本地收听次数提高权重（有上限）。收听次数由播放器开始播放事件记录，不把每10秒进度保存误算成一次收听。旧资料库缺计数字段时可继续读取。

对候选进行当前规则过滤，去掉已订阅节目、重复 feed ID；兴趣分类得分减去已经推荐过的分类/发布账号惩罚，每个发布主体最多两项。没有偏好时以按日轮换的正向主题做冷启动。缓存中的候选可在订阅/收藏/规则变化后立即重新排序，无需把本地历史发送到服务端。

评分和历史留在设备；检索会向 Apple 发送分类关键词和地区，RSS 请求发给发布者。没有独立追踪服务。

## 缓存、刷新与配额

首开联网获取；启动先读取私有 discovery.json。栏目默认24小时刷新，订阅默认一小时检查（失败也记录尝试时间），手动刷新另有一分钟节流。各发现栏目失败保留上次有效缓存，不清空资料。缓存不保存“永久已授权”结果，展示时总是使用当前策略重算。

统一 HTTPClient 为 iTunes 搜索、Lookup 与旧版榜单预留3.2秒请求间隔，含重试。现代榜单每天少量调用；目录/RSS支持缓存、超时、取消和有限重试。Lookup按批次请求，RSS并发4。发现磁盘缓存最多40个栏目、160个节目；被淘汰依赖的栏目过期以便下次重建。系统 URLCache 和独立发现缓存分工：前者遵循 HTTP/短时缓存，后者提供跨启动与断网回退。没有关闭 App 后定时执行或服务端推送。

缓存节目记录 RSS 获取时间，旧发现缓存不能覆盖新 RSS 元数据；目录的分类/账号观察保留原获取时间，不通过读缓存假装重新确认身份。缓存版本/修订号防止并发栏目结果把较新的状态覆盖成旧状态。

## 分类、发布账号及统一授权

家长 PIN 页面展示全部110个标准分类与子分类。禁用父类继承到全部子类；只禁用子类保留父类和兄弟类。设置保存在 Keychain 家长策略，可经覆盖升级保持。儿童分类入口、当前已打开的分类页、搜索、首页、榜单、推荐、历史、队列、订阅、下载与播放均使用当前 ContentFilter。

未禁用的分类中的节目仍必须通过发布账号、关键词和节目/单集名单。家长更具体的单集/节目 allow 仍可以显式纠正误拦截，但不会重新显示整个被禁用的分类入口。关闭过滤则按原产品模式关闭这些限制。

发现只展示 allow；review 和 block 都不能通过补充候选重新放行。实际播放/下载时仍再次校验，推荐展示不授予执行权限。
