# 听芽 1.1.4（7）：单集搜索、完整订阅栏与刷新反馈

日期：2026-11-02（香港时间）。基线：`main` / `712fa2c`，1.1.3（6）。直接在现有 main 完成，无额外分支或 worktree。

## 功能与来源

参考综合、节目、单集分组界面的功能设计；采用其中综合、节目、单集的区分，以及单集标题、日期／时长、播放和节目入口的功能；听芽沿用自己的颜色、原生分段选择器、列表、详情、播放器与封面组件，没有复制 Apple 品牌素材。

- 搜索增加“综合／节目／单集”。综合中分组显示节目和单集；单集显示自身标题、所属节目、可用的日期／时长，可进入详情和播放。RSS 对齐后复用已有收藏、下载等操作及权限 gate。
- 本机搜索覆盖已经加载到资料库的 RSS，包括订阅、曾经查看的未订阅节目，以及启动时合并的已有探索缓存。检查单集自己的标题、简介及 RSS 文字元数据；多个空白分隔词均须命中，不会因节目名称匹配而挑选其最新几集。大小写、全角及重音差异按折叠文字处理。
- 远端使用 Apple **公开文档明确列出的** Search API `media=podcast&entity=podcastEpisode`，与原有节目搜索分别请求 CN、HK、US，每个地区每种类型最多 20 条。官方说明及限流：[Apple Search API](https://performance-partners.apple.com/search-api)。继续使用已有约 3.2 秒目录请求间隔、HTTP 缓存、取消检查和搜索代次保护；六个渠道的补充会受此限流影响，并非承诺瞬间返回全部结果。
- 目录候选还必须在单集自身标题／简介命中输入，过滤掉只因节目名或目录隐藏排序信号返回的条目。公开目录不是全量历史库，地区、出版者收录、源站可用性和 RSS 历史保留均会影响覆盖；不会宣称等同 Apple Podcasts App 的内部检索。
- 本机搜索与目录请求并行，陆续发布结果。本机匹配使用后台任务及现有已校验展示 ID；未知或正在重建的展示状态按当前正式过滤器校验，不在主 actor 重算全库。搜索结果是暂态，不再每个目录更新都合并资料库、保存和重建全库展示。
- 搜索期间不请求任何候选 RSS。打开或播放目录单集时，先按其稳定节目 ID 执行公开 Lookup，要求返回的 RSS 身份与候选一致；再只加载这个节目的 RSS。按 GUID 唯一匹配；没有 GUID 时才按完整 enclosure URL 唯一匹配。冲突、歧义、已移除单集或变更的 RSS 身份均报告失败，不用同名标题猜音频，不直接播放目录 `episodeUrl` 或 `previewUrl`。
- 跨地区按节目／单集目录 ID 去重；本机与目录按同一 RSS 下的 GUID／enclosure 对齐去重，同名不同节目保留。快速换词或清空后，旧代次的响应不能恢复旧列表；部分渠道失败保留其余结果，全部远端失败时保留本机命中并明确提示来源失败。节目和单集的空状态分别判断。
- 中文第一次 Return 仍由现有 UITextField 提交已组合文字并收起键盘。每次用户提交只调用一次家长搜索记录逻辑，六个渠道不重复累计；记录继续独立保存并需 PIN／grant 才能查看和删除。

## 权限与兼容

目录候选不是可播放资料库单集。显示继续执行现有家长过滤，未知元数据保留 review 策略；操作前仍使用当前 RSS 单集和实时 gate，不能用搜索展示结果代替授权。单集禁止仍优先于节目允许；分类父子限制、节目／单集例外及正式词库未改。新鲜的 RSS 缓存仍采用新到的目录分类／发布身份并复核队列、播放和下载；相同缓存对象不会因空值归一化触发无意义保存。

保留 1.1.3 的后台初始化、展示快照／缓存失效、本地下载快速呈现、合并保存、详情新鲜度、家长拦截详情成功／失败反馈。Bundle ID `org.quietcast.family`、最低 iOS 16、存储 schema／路径、Keychain service／account、PIN 参数和下载 session 身份均未改变。未清除原始订阅、收藏、历史、进度、下载、队列或黑白名单。

正式词库仍为 `fiction-zh-2026-10-27-v1`；App 内资源和 `rules/fiction-audiobooks.json` SHA256 同为 `b1d875e5b49415f74c111389f0ec1b3c189abc37cdc547dd5c21e18d3393d765`。

## 订阅栏

原实现虽有横向 ScrollView + LazyHStack，但 `prefix(8)` 让第 9 项以后根本不进入视图数据。未找到能证明该常量是经过性能测量决定的记录，不能推断“因为性能所以必须限 8 个”。

现在直接读取现有已经过滤、排序的 `presentation.subscribed`，无额外过滤、排序、持久化或 RSS 请求。封面继续由 LazyHStack 内已有 AsyncImage 组件按可见区域创建。“全部节目”改为“订阅列表”，仍可进入独立完整列表。

## 追加排查：9 个节目暂时无法更新

旧提示只表示循环捕获了 9 次错误，不能区分 RSS 失效、网络失败、存储错误和任务取消。本轮在隔离的 13 个订阅夹具里，先成功更新 4 个、在第 5 个请求取消任务，实际复现完全相同的“9 个节目暂时无法更新”提示：第 5 个取消和后面 8 个根本未发送的请求，都被旧代码累计成失败。证据：`build/refresh-cancellation-before.log` / `build/delivery/refresh-cancellation-before.xcresult`。

修复后取消会停止循环，不再把未请求的节目记成失败，也不再为取消弹出 RSS 更新失败提示；已完成的更新保留，恢复之前的尝试时间以允许立即重试。真正失败仍保留原有退避及本地数据，并在订阅页新增“更新详情”，分别显示实际失败的节目及连接超时、断网、HTTP 状态、RSS 解析或存储原因。详情同样过滤家长禁止显示的节目。取消只显示“更新已中断”，不声称整批更新完成。

针对公开 RSS 的补充诊断未发现当次 Mac 网络下的源站异常；此结果不能反推其他设备当时的网络情况。个人订阅快照和设备资料不进入公开仓库，真实错误应以 App 的更新详情为准。
